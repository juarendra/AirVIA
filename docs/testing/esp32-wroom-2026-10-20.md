## Scope

This record captures smoke testing performed against the AirVIA application and the matching WROOM firmware. It is evidence for testing readiness, not production certification.

## PASS

- [x] WROOM definition loaded in AirVIA UI. Matrix rendered as 5x6; encoder count 1; lighting none.
- [x] Firmware native tests passed: `protocol_test`, `esp32_ble_hid_test`, `esp32_ble_transport_test`, `esp32_shared_server_test`, `esp32_nvs_test`, and `esp32_gpio_test`. Each printed `All tests passed!`; aggregate exit `0`.
- [x] WROOM Arduino CLI compile passed with `esp32:esp32:esp32`. Flash usage: 625899/1310720 (47%). RAM: 39660/327680 (12%).
- [x] Firmware uploaded successfully through the CP210x serial adapter. esptool identified ESP32-D0WDQ6 revision 1.0; all written regions reported verified hashes.
- [x] Serial boot completed: NVS initialized, HID service initialized, FF60/FF61/FF62 service initialized, server advertising started, protocol initialized, keyboard initialized, device ready.
- [x] BLE advertisement discovered the HID service `1812` and VIA service `FF60`.
- [x] FF62 read returned firmware version `1` and device name `AirVIA WROOM32`.
- [x] FF61 32-byte protocol request returned VIA protocol `0x000D`.
- [x] Read-only synchronization completed: 3 layers, 180 keymap bytes / 90 keycodes, encoder layer-0 values, layout options, and macro metadata.
- [x] Reversible keymap persistence round-trip passed: original first key `0x0010`, temporary `0x0004`, restore `0x0010`, commit command `09 02`, reconnect readback `0x0010`.

Direct GATT verification used temporary local Python Bleak tooling. Bleak is not an AirVIA repository dependency.

## Reported failure

- [ ] User connected matrix pins directly and reported no key response. This was not independently reproduced in this run.
- [ ] Current firmware uses `kColToRow`; first wiring must include column pull-ups and one diode per switch with the documented orientation. Directly shorting GPIOs is not a valid matrix acceptance test.
- [ ] AirVIA's browser-native Web Bluetooth chooser did not complete through isolated browser automation. The page loaded and exposed Web Bluetooth, but the UI did not reach connected state. Direct GATT passed independently.

## Remaining tests

1. Wire one switch only: R0/GPIO4 to C1/GPIO16, with a 10 kΩ pull-up from GPIO16 to 3V3 and a diode from column toward row; verify one key event.
2. Add C2–C5 one at a time: GPIO17, GPIO18, GPIO21, GPIO22; verify expected row/column mapping.
3. Verify all matrix rows and columns, debounce, release, layer keys, modifiers, 6KRO, and no stuck keys.
4. Test encoder GPIO33/GPIO32 after confirming physical encoder wiring. Current WROOM example still consumes and discards encoder delta; encoder HID action is not accepted yet.
5. Run browser-visible Web Bluetooth pairing in Chrome/Edge and verify AirVIA UI state transitions, not only direct GATT.
6. Perform hard power-cycle persistence test with the saved keymap.
7. Rebuild against the CI-pinned ESP32 core version `3.1.0`; local smoke used core `3.3.0`.
8. Materialize the 8-file firmware candidate as a reviewed commit/manifest before release use.
